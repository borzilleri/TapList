# wbf-2026 dataset — parsing notes

`wbf-2026.json` was hand-converted (one-time) from `wabf-2026.csv` (the source list, kept
alongside this file) against `public/schema/dataset.schema.json`. There is no reusable converter
script — the source CSV is irregular enough that the rules below plus the manual touch-ups
are what reproduce this output. If the list is re-issued, re-apply these.

## General rules applied to the `Style/ABV` column

The column fuses ABV and style in inconsistent orders/separators. For each cell:

1. **ABV** = the first numeric token that is an ABV — a number optionally followed by `%`
   and/or `ABV` (case-insensitive). A bare number (no `%`) is taken as ABV when it's clearly
   the ABV token (e.g. `5.0 American Lager`, `7.2 WC IPA`, `6.6 ABV`). `IBU` numbers are
   not the ABV (`6.5% 60 IBU` → `6.5`; see the IBU rule below). Explicit `0%`/`0.0%` → `0`. No numeric token (`Pale Ale`,
   `Lager`, `Hop Water`, `N/A IPA`, `TBD`) → `abv` omitted.
2. **style** = the cell with the ABV token, surrounding separators (`-`, `/`, `|`, `,`, `;`,
   stray `ABV`), `N IBU` clauses, and wrapping quotes stripped, then trimmed. Empty → omitted.
   Any stripped `N IBU` clause is appended to the beer's `description` (bare, e.g.
   `… ale yeast. 60 IBU`, matching how other rows carry IBU inline) unless the description
   already mentions IBU. Only two rows triggered this: Rainwater IPA (`wbf26-0149`, 60 IBU) and
   Rufous Hummingbird Hazy Pale (`wbf26-0151`, 45 IBU).
3. Style casing is left **verbatim** from the source (so `session IPA`, `hard kombucha`,
   `West Coast Ipa`, `fruited cider` are intentional, not typos to fix).
4. The CSV has **no location data**, so no beer has a `location` field.
5. Empty optional fields are omitted rather than emitted as `null` (the runtime parser treats
   absent and `null` identically — `src/lib/data.ts`).

Beer ids are sequential `wbf26-NNNN` in CSV row order over the *kept* rows.

## Manual touch-ups (per-row judgment — not derivable from the rules)

- **7 Seas Brewing Co — Heidelberg** (`wbf26-0009`): the `Style/ABV` cell held a *description*
  (`4.0% ABV; Brewed on a base of NW pilsner malt...`) and the Description column was empty.
  Set `abv: 4.0`, no `style`, and moved the prose into `description`.
- **STRUCTURES BREWING — TROPICAL DREAMS** (`wbf26-0182`): the `Style/ABV` cell mixes a style
  label, the fruit list, and the ABV (`Traditional Sour Smoothie! Pineapple, Mango, Passion
  Fruit, and Coconut! 7.2% abv`). Split it: `abv: 7.2`, `style: "Traditional Sour Smoothie"`
  (trailing `!` dropped for a clean label), and the remaining fruit-list prose
  (`Pineapple, Mango, Passion Fruit, and Coconut!`) prepended to the genuine Description-column
  write-up. Both columns are real data for this beer; nothing was dropped.
- **Offset Ciderworks — Off Dry / Peach**: each appeared **twice, verbatim** in the CSV. Kept
  one of each (`wbf26-0128`, `wbf26-0129`); dropped the duplicates.
- **Culture Shock Brew — "Golden Griffin (see above)"**: an empty placeholder row (no
  style/ABV, no description). **Dropped.** The real "Golden Griffin" (`wbf26-0039`, has a
  description) is kept.
- **Rooftop Brewing Co — Cask Beer** (`wbf26-0157`): `Style/ABV` was `TBD`; omitted both
  `abv` and `style`, kept the description.
- **Modern Nature Wines** (`wbf26-0122`–`0125`): these are wines, not beer, but were listed.
  Kept as-is with the varietal as `style`.

Result: **218 beers** (221 unique source rows − 2 Offset duplicates − 1 placeholder).

## styleCategory (normalized style filter)

The free-form `style` is too inconsistent to filter on (140+ distinct values), so each beer also
carries a `styleCategory` from a fixed set of 12 buckets, used by the list-view style filter:
`IPA`, `Pale Ale`, `Lager & Pilsner`, `Wheat`, `Stout & Porter`, `Sour & Gose`,
`Saison & Farmhouse`, `Belgian & Strong`, `Amber, Brown & Dark`, `Blonde, Kölsch & Cream`,
`Cider`, `Other`.

This field is **generated**, not hand-authored: run `scripts/categorize-styles.ts` to (re)populate
it across any dataset JSON:

```
npx tsx scripts/categorize-styles.ts public/data/wbf-2026.json public/data/taplist-mock-2026.json
```

The script applies ordered keyword rules (first match wins) against the lowercased `style`; the
exact rules and ordering live in that file. Two ordering choices worth knowing:

- **Lager is checked before Pale** so dark/pale lagers (`Czech Pale Lager`, `Munich Dunkel`,
  `Schwarz Lager`, `Amber Lager`) land in `Lager & Pilsner`, not `Pale Ale`/`Amber, Brown & Dark`.
- **Stout/Porter is checked before Belgian & Strong** so barrel-aged stouts (`BBA Stout`) stay in
  `Stout & Porter` while `BA Barleywine` / `BBA Strong Ale` land in `Belgian & Strong`.

Missing/empty `style` and anything unmatched fall through to `Other` (this is where the non-beer
entries land: seltzer, hop water, kombucha, soda, and the Modern Nature wines). A few rows the
rules can't infer are pinned by id in the script's `OVERRIDES` map (the Offset Ciderworks rows with
bare labels — `(off-dry)`, `(semi-sweet)`, `Dry Apple` — forced to `Cider`), so re-runs stay
idempotent. After running, eyeball the `Other` bucket and any new edge cases before committing.

## Catalog note

`public/data/catalog.json` points the default entry at this dataset. The `dates`
(2026-06-12/14), `location` (Marymoor Park, Redmond WA), and `status` (upcoming) were carried
over from the previous placeholder entry and **should be verified against the real event
details** before shipping.
